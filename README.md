# Tavern API Desk

酒馆 API 管理扩展，兼容 SillyTavern 与 TauriTavern。基于 [ST-Quicker-Api](https://github.com/qianzhuowo/ST-Quicker-Api) 3.8.6 改造，遵循 GPL-3.0，保留原作者署名及原生密钥校验、切换与回滚机制。

## 功能

- 多 API 配置：新增、重命名、复制、删除、收藏；按名称、地址和模型搜索，按格式筛选。
- OpenAI Compatible、Anthropic、Gemini；TauriTavern 宿主支持时显示 Custom 子协议与 OpenCode Zen / Go。
- 每个配置独立管理模型：拉取、手动添加、搜索、选择和排序。
- 使用原生 Secrets 或 Reverse Proxy Presets 管理凭据。新线路未填写密钥时使用空密钥，不沿用其他线路的密钥。
- 对话补全预设绑定，以及“预设 + API 配置 + 模型”的快捷方案。
- 未保存修改提示、设置保存状态与失败重试；Ctrl/Cmd + S 保存并应用。
- 导入原生配置、迁移同一实例中的 Quicker API 数据；JSON 备份合并导入。
- 桌面配置列表与编辑区分栏；窄面板和手机采用单列，可点击右上角展开工作台。

## 安装

在酒馆的扩展管理界面选择安装扩展，填入 Git 地址：`https://github.com/JinSheng-oam/Tavern-API-Desk.git`。TauriTavern 支持的地址和认证方式取决于宿主版本；请使用该版本支持的 Git 仓库地址。

先停用 Quicker API、API Hub 等其他连接管理扩展，再刷新。扩展检测到这些面板时会停用，避免相互修改连接。

**SillyTavern 手动安装：** 将整个 `Tavern-API-Desk` 文件夹放进当前用户的 `data/<用户句柄>/extensions/`，然后刷新页面、确认扩展已启用。具体数据目录和全局安装位置取决于宿主版本和配置。文件夹内应直接包含 `manifest.json` 和 `index.js`。

**TauriTavern：** 在实际用户数据目录中，将文件夹放进 `data/default-user/extensions/Tavern-API-Desk/`（当前用户），或 `data/extensions/third-party/Tavern-API-Desk/`（全局）。数据目录具体位置取决于宿主配置；不同用户应使用对应的用户目录。同名本地扩展优先于全局扩展。重启或刷新后在扩展列表中启用。可参考宿主的 [扩展开发文档中的目录约定](https://github.com/Darkatse/TauriTavern/blob/main/ExtensionDEV.md#11-扩展目录)。

这是原生扩展，不是酒馆助手脚本；不要在酒馆助手的脚本导入入口导入扩展目录或单独的 JS 文件。

## 开始使用

1. 打开酒馆的 API 连接设置，选择聊天补全。
2. 点击 API Desk 的新增按钮，填写名称、接口格式、API 地址、密钥和模型。
3. 点击“保存并应用”。保存状态以宿主确认响应为准；“已应用”指连接配置已写入，不代表服务商连通性或余额已验证。
4. 配置列表或选择框中的选择会立即应用该配置；有未保存编辑时会先询问。重新应用会恢复已保存内容。
5. “获取模型”用于拉取服务商可提供的模型，不会发送聊天消息；模型接口是否可用取决于宿主及服务商。
6. 使用“快捷方案”组合预设、配置与模型，发送栏入口的位置可在方案管理中设置。

Anthropic / Gemini 的空 API 地址表示官方端点，填写地址则按原生反向代理处理。OpenCode 仅接受 `zen`、`go` 或对应官方地址，Go 不支持 Gemini。各格式支持范围由宿主能力决定。

保存 API 配置会绑定当前对话补全预设；同一配置可用于多个预设并记住各自模型。快捷方案按“预设 → API 配置 → 模型”执行。修改模型后若希望保留为某个预设的默认模型，请更新该原生预设。

## 迁移与备份

**同一实例迁移 Quicker API：** 停用旧插件并刷新后，点击“迁移 Quicker API”。复制配置、模型和快捷方案，保留当前用户的原生密钥引用，不删除旧数据，不覆盖已有 API Desk 预设绑定。迁移确认后仍需选择配置以重新校验原生密钥。支持参考插件 schemaVersion ≤ 15。

**跨实例备份：** 点击“导出备份”得到 JSON，再在目标实例导入。导入会合并并重新分配 ID，重名自动加序号，现有预设绑定优先，当前连接保持原样。

便携备份不含密钥、密钥引用、代理密码、附加 Body 或 Headers；迁移后需重新填写。API 地址、模型名与排除规则仍包含在备份中，分享前请自行检查。不要将不希望被备份的秘密放在名称、模型名或排除规则里。

## 密钥查看

日常保存与切换不需要开启密钥明文权限。查看和复制已保存密钥需要宿主允许显示密钥：SillyTavern 使用 `config.yaml` 的 `allowKeysExposure`，TauriTavern 使用其独立设置中的“允许显示密钥”。是否开启由用户决定，扩展不会更改此权限。

## 验证范围

有纯数据与平台适配单元测试，以及使用模拟宿主和内存账户数据的 Chromium 浏览器回归。真实 API 请求、真实密钥权限、具体已安装宿主版本和不同主题仍应在实际环境验证。卸载只移除扩展文件；宿主中的原生密钥、扩展设置和最后应用的连接仍会保留。
